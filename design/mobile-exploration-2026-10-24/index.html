Design review, references & scope

I inspected the running iOS inbox and sliding mailbox panel, the current SwiftUI screens, the committed reader/compose screenshots, and the earlier design studies. The compact header and folded-m mark are strong foundations. The category is easy to overlook, read/unread rows have similar visual weight, and the main actions all require reaching the top. These concepts test different answers to those problems.

Each direction has a custom inbox and reader using the same fictional conversation. References inform patterns, not exact screen replicas. Shown palettes are art directions; a shipped version should support adaptive light/dark appearance, Dynamic Type, VoiceOver, native safe areas, and at least 44-point touch targets. Directions 01–05 mainly reorganize existing controls. Directions 06–10 introduce new grouping, home views, or navigation behavior; their implications are listed per concept. No iOS application code is changed.
